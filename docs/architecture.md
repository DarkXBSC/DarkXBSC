# Dark 架构与权限

## 用户路径

发行：用户钱包 → 图片/metadata（Flap IPFS）→ 选择实时底池 → 链上核对启用状态与精度 → 地址盐计算 → `eth_call` → 估 Gas → 用户签名 → 2 次确认 → 核对代币地址与名称 → 可选 Registry 登记。

OTC：卖方选择精确出售/收款资产与数量 → ERC20 授权 → EIP-712 签名 → 私下分享 JSON → 买方核对签名、域、nonce、资产、费用、最低到账 → 授权 → 合约原子结算。支付币必须足额转账，出售币的转账税由最低到账限制。成交交易在公链公开。

库存：规划器只计算用户填入的同币种估值。`TigerInventory` 将资产交给指定接收方，正确 secret 只能在到期前领取；到期后仅退回原发送方。跨链双方必须先核对相同 secret 哈希和错开的到期时间，不能提前泄露 secret。Robinhood 未部署，所以当前双链交割未开放。

## 权限表

| 合约 | 权限主体 | 能做什么 | 不能据此宣称什么 |
| --- | --- | --- | --- |
| TigerRegistry | 登记者、部署管理员 | 自己登记/更新；管理员 attest | 不是所有权证明或价格担保 |
| TigerSettlement | 报价卖方、合格买方 | 撤自己的 nonce；按签名条款交换 | 没有管理员提款，不是匿名链上成交 |
| TigerInventory | 任意触发者，固定收款规则 | 正确 secret 领取、到期退款 | 不铸币、不自动保证对手链履约 |
| TigerReserveFactory | 官方 VaultPortal | 每个 token 创建唯一 Reserve | 不代表 Flap 低风险审批或上架批准 |
| TigerReserve | token 创建者、官方 Guardian | 同步收入、支取、立即救援、恢复 | 不是锁死金库；创建者有即时控制权 |

Reserve 的救援将所选资产全部转给不可变的创建者，并暂停普通提款；救援 quote 时重置记账基线，防止后续记账假溢出。创建者由原生发射流程传递。先创建 Vault、后创建 Token，所以构造函数不能依赖尚不存在的 TaxToken 代码。

## 身份与恢复

Agent OTC 使用 BSC 官方 `0x60B9262456dE011F7d15a54CdD8c48bAaa8B022F` 的 `balanceOf`，结算时 maker 与 taker 都必须持有 NFT。连接钱包与持有 Agent ID 是两个状态。普通 OTC 不要求 NFT。

网站在调用钱包前持久保存 chain/from/to/data/value/nonce 意图；返回 hash 后记录本地活动。钱包响应未知时阻止同账户同链新提交，使用钱包历史中的原 hash 恢复并验证完整意图。用户拒绝会清除意图。链上确认之后才标为成功；页面刷新不应变成重新花钱。不能拿一个无关成功 hash 清除未决提交。

此恢复日志仅在用户浏览器内，不是服务器数据库；清理浏览器数据会删除本地恢复线索。执行未知时保留钱包历史与 hash，不自动重发。

## 本地服务与密钥

API 仅监听 127.0.0.1，并校验 Host/Origin。仅把 .env 中两个 RPC 配置放入服务内存，部署私钥不进入 API 业务配置。不提供 `eth_sendRawTransaction`、任意目标抓取、任意 factory 或部署签名接口。图片目录代理只接受已知链+地址、来源限制到 Flap HTTPS 主机，不跟随重定向，并限制响应体积。

部署脚本是独立本地工具，具有预算、链/账户、编译输入哈希、nonce、签名日志、广播恢复检查。网站构建不得包含 .env 或 `deployments/private`。公开编译输入包含全部依赖源码，足以复现源码验证。
